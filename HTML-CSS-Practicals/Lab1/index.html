Lab 01: Starting A Git Repository

Practical tasks, programs, expected outputs and viva questions

Experiment No. 1
Complete the tasks below in order. Read the aim and procedure, study the program, and verify the expected output in your browser.
Task 1

Configure Git for the lab repository

Aim: To create a lab folder, initialize Git, and configure repository-specific identity.

Theory: Git is a distributed version-control system. A repository stores project history. `git config --local` writes identity settings only to the current repository.

Procedure: e Create `html-lab`; enter it; run `git init`; set local user.name and user.email; display both values.

Program / Commands

mkdir html-lab
cd html-lab
git init
git config --local user.name "Student"
git config --local user.email "student@example.com"
git config user.name
git config user.email
Expected output: Git initializes an empty repository and prints the configured name and email.

Result: The repository was initialized and local Git identity was configured successfully.

Viva-Voce Questions

  • What is Git?
  • What does git init do?
  • What is the purpose of --local?
Task 2

Create and commit the home page

Aim: To create an HTML file, inspect its status, stage it and save it in Git history.

Theory: Git tracks changes in the working tree. `git add` stages changes and `git commit` records the staged snapshot.

Procedure: e Create index.html; check status; stage the file; commit with the required message.

Program / Commands

cat > index.html <<'EOF'
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Home</title></head>
<body><h1>Welcome to the HTML Lab</h1></body>
</html>
EOF
git status
git add index.html
git commit -m "Add home page"
Expected output: The status first shows index.html as untracked; after staging and committing, Git reports one file changed.

Result: The home page was added to the repository in a commit.

Viva-Voce Questions

  • What is the staging area?
  • What does git status display?
  • Why are commit messages useful?
Task 3

Add a heading and inspect commit history

Aim: To update the HTML page, create a second commit and view the concise history.

Theory: A commit represents a saved project state. `git log --oneline` displays abbreviated commit identifiers and messages.

Procedure: e Add an h2 below the h1; save; stage and commit; display the log.

Program / Commands

# Add this line below the h1 in index.html:
<h2>Next Lab Meeting</h2>
 
git add index.html
git commit -m "Add next meeting heading"
git log --oneline
Expected output: The log lists two commits, with the newest commit first.

Result: The second change was committed and the repository history was displayed.

Viva-Voce Questions

  • What is a commit?
  • What does --oneline do?
  • Which commit appears first in git log?
